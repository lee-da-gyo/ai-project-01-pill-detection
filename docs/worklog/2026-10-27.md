- 사용 금지 데이터를 확인했다: AI Hub 경구약제조합 5000종의 TL_2_조합.zip, TS_2_조합.zip

  - 라벨은 COCO 형식이지만 **JSON 하나에 알약 하나**만 있고, 조합 폴더 / 약 코드 폴더로 흩어져 있다. 이미지별로 합쳐야 한다.
  - 클래스 56종. `category_id`는 약 코드 숫자라서 YOLO용으로 0~55로 다시 매겨야 한다.
  - 이미지당 알약 수: 3개 157장, 4개 75장
  - 촬영 조건: 배경·조명·크기가 모두 같다. 카메라 각도만 70/75/90 세 가지다. 앞면이 92%다.

## 발견한 문제 (인사이트)
1. **데이터가 적다**: 학습 232장으로 테스트 842장을 맞혀야 한다. 사전학습 모델 파인튜닝과 증강이 필수다.
2. **클래스 불균형**: 최다 153개(일양하이트린정 2mg)부터 최소 3개까지
3. **라벨 누락**: 파일명상 알약 수보다 박스가 적은 이미지가 8장 있다. 그대로 쓰면 빠진 알약이 배경으로 학습된다.
4. **잘못된 박스**: `K-003351-016262-018357_0_2_0_2_75_000_200.png`의 x=6567로 이미지 폭(976)을 넘는다.

## 추가로 한 일 (저녁) – 전처리 노트북 `02_preprocess.ipynb`
- 라벨을 검증할 **독립적인 기준**으로, 배경 차분(Lab 색 거리 + Otsu)으로 알약 영역을 분할했다.
- 라벨 박스와 분할 영역을 대조해 라벨을 감사했고, 오류 유형별 규칙으로 자동 수정했다 → **10건 수정**
  (범위 밖 1, 엉뚱한 위치 1, 누락 8). 전/후 그림으로 전부 눈으로 검수했다.
- **실수와 교훈**: 처음 만든 "빈 박스 이동" 규칙이 6건을 고쳤는데 5건이 오탐이었다.
  반투명 캡슐(OMACOR)과 파란 알약은 분할이 잘 안 돼서 "박스 안이 비었다"고 잘못 판단한 것이다.
  → "원래 박스와 겹치지 않고 크기가 비슷한 알약일 것"이라는 조건을 더해 1건(진짜 오류)만 남겼다.
  자동 규칙은 반드시 결과를 눈으로 확인해야 한다는 걸 배웠다.
- 박스 보정: 분할 박스와 라벨러 박스의 테두리 차이(중앙값)로 새 박스를 라벨러 기준에 맞췄다.
- 조합 단위 Stratified Group 5-Fold로 나누고 누수가 0인지 `assert`로 확인했다.
  fold마다 val에 train에서 못 본 클래스가 1~7개 있다 (1개 조합에만 있는 클래스 때문).
- YOLO 라벨을 다시 읽어 픽셀로 되돌려 비교했다 (최대 오차 0.001px).
- 기술 메모: Windows에서 `cv2.imread`는 한글 경로를 못 읽어서 PIL로 읽었다.

## 추가로 한 일 (밤) – 저장소 정리와 계획 재수립

  스프린트 프로젝트가 3개라서 이름을 `ai-project-0N-주제` 패턴으로 통일했다.
- README를 포트폴리오용으로 다시 구성했다 (핵심 성과, 파이프라인 다이어그램, 그래프, 검증 전략).
- **계획을 다시 세웠다.** 처음 일정표는 단순했고, 가이드를 다시 대조해 보니 빠진 항목이 많았다
  (모델 비교, 하이퍼파라미터 튜닝, 증강, 파이프라인 자동화, 시연 영상 등).
  가이드의 모든 항목을 요구사항 추적표(R1–R17)로 만들고, 산출물·완료 기준·날짜를 붙였다.
- 핵심 설계 결정: **2단계 구조 (YOLO 검출 + CNN 분류기)**
  - 근거: 56종에 비해 박스가 771개뿐이고 29종은 10개 미만이다. 검출은 사실상 "알약이냐 아니냐" 문제라 데이터가 충분하다. 종류 판별은 crop 분류기에 강한 증강을 주는 편이 유리하다.
  - 가이드의 VGG / ResNet / YOLO 비교도 이 구조 안에서 자연스럽게 수행된다.
  - 단일 YOLO 베이스라인과 같은 fold에서 비교해 실제로 나은지 확인한다.
- 도메인 지식 활용 아이디어: 이미지당 알약 최대 4개(`max_det=4`), 같은 약 중복 없음

## 추가로 한 일 – 코드 구조화 (파이프라인 자동화)
- 문제: 코드가 노트북 셀 안에만 있어서, 학습·추론 노트북에서 같은 코드를 다시 복사해야 하고 리뷰어가 코드를 찾기 어려웠다.
- 해결: 공통 로직을 `src/pilldet` 패키지 8개 모듈로 분리했다 (config, data, boxes, segment, clean, split, export, viz).
  - `scripts/prepare_data.py`: 데이터 준비 전체를 명령 한 줄로 실행 (8.7초), 로그는 `reports/logs/`에 저장
  - `tests/test_core.py`: IoU, 좌표 변환 왕복, 파일명 파싱, fold 누수 방지 등 단위 테스트 11개 통과
  - 노트북은 패키지를 불러 쓰고, 핵심 함수의 실제 코드를 `inspect`로 노트북 안에 함께 보여 준다
- **검증**: 리팩터링 전후의 산출물(label_fixes, folds, class_map, COCO)을 `git diff`로 비교 → **완전히 동일**
- Kaggle에서는 노트북이 GitHub 레포를 clone 해서 같은 패키지를 쓴다
